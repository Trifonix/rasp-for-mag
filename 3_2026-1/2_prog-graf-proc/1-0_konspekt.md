# Конспект лекции — Программирование графических процессоров  
**Дата:** 07.09.2026

## 1. Внедрение ПО (вводная часть)

- Создание продукта без внедрения почти бесполезно: нужен **план** и **журнал внедрения**.
- В журнале ежедневно фиксировать, что происходит с продуктом по выбранной схеме тестирования.
- Если схема не работает — **корректировать план**, а не бросать процесс.
- Версии публиковать открыто: alpha → beta → исправленные релизы (как в индустрии).
- Даже у крупных пакетов (пример: Houdini) огромные ресурсы уходят на внутреннее тестирование.

## 2. Возможности «тяжёлой» графической оболочки (пайплайн)

Структура (типа Houdini) закрывает этапы **внутри себя**:

| Этап | Содержание |
|------|------------|
| Моделирование | процедурная геометрия / обработка |
| Lookdev | внешний вид, свет, рендер, композитинг |
| FX | pyro, real-time, разрушения, FLIP и др. |
| Анимация | риггинг, монтаж движения |
| Groom | мех, волосы, перья |
| Игры | встроенные связки с Unreal / Unity |
| Миры | рельеф, океаны, облака, растительность |
| Crowds / AI | отдельный «маленький» контур |

## 3. ИИ в контексте лекции

- По позиции преподавателя: ИИ — **векторная структура**, решающая элементарные задачи (в т.ч. через СУБД / запросы), а не «бог».
- В графическом пайплайне ИИ — лишь один из модулей, не центр системы.

## 4. Главная тема пары: программирование в графике = ноды / ООП-модули

**Суть:** в графических оболочках «программирование» — это чаще всего:

1. **Нодовая (node) система** — граф узлов и связей;  
2. **Древовидная структура** — иерархия объектов / операторов;  
3. **ООП-модули** — блоки с полями, вызовом функций, подключением каналов.

### Что важно понять (критерии «голова работает»)

- Где **начало** графа / дерева и почему так.
- Как соединяются блоки: ресурс → блок → результат.
- Как подключаются каналы: **RGB**, **Alpha**, нормали, металличность и т.п.
- Как подключаются **свет** и **математика** (узлы операций).
- Как внутри вызываются функции / модули (аналог ООП в коде).
- Как считаются **физические** эффекты (аттракторы, падения, столкновения) — хотя бы на уровне схемы.

### Инструменты, которые разбирали / предлагали смотреть

| Пакет | Комментарий с пары |
|-------|-------------------|
| **Houdini** | «чистый» нодовый подход, сильный пример программирования в графике |
| **Maya** | нодовая система (смотреть ноды, не уходить в сырой код) |
| **Rhino + Grasshopper** | визуальное ООП / вызов функций узлами |
| **Blender** | можно, но осторожно: аддоны платные/нестабильные между машинами |
| **Substance** | нодовая работа с материалами / картами |
| **Marmoset** | пример из списка «передовых» инструментов |
| **Cinema 4D** | нодовая структура = тоже программирование |
| **ZBrush** | скорее скульпт / «слепок», не чистые ноды |

«Чистые» примеры программаторского подхода в графике: **Houdini**, **Grasshopper**, нодовое поле в **Houdini/Solaris**.
